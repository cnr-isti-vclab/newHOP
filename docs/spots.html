Spots

The spots block defines named three-dimensional hotspots with a small, purpose-built configuration. They are separate from objects so interface annotations and pickable scene content remain distinct. Spot identifiers are unique within the spots block; an object may use the same identifier because objects have their own namespace.

Spots Block Example

Built-in primitive

spots: {
  hotspotA: {
    primitive: 'sphere',
    label: 'Feature A',
    size: 50,
    position: [-300, 0, 200],
    rotation: [0, 0, 0],
    scale: [1, 1, 1],
    color: 0xff4d6d,
    alpha: 0.7,
    transparent: true,
    doubleSided: true,
    visible: true,
    tags: ['annotation'],
    clippable: false,
    measurable: false,
  },
  hotspotB: {
    primitive: 'cube',
    size: 50,
    position: [100, 0, 200],
    color: 0x4ade80
  }
}

Custom geometry or model

A spot can instead use supplied geometry or a custom PLY/OBJ file. The source replaces primitive, and custom sources remain unlit.

spots: {
  marker: {
    file: 'models/marker.obj',
    position: [10, 20, 30],
    scale: 0.5,
    color: 0xffc857
  },
  custom: {
    geometry: new THREE.SphereGeometry(2, 24, 16),
    position: [0, 0, 0]
  }
}

Spots management at runtime

Use the Presenter to list, add, and remove spots at runtime. Spot names have their own namespace and may match an object name. Shared placement and visibility properties keep spots convenient to author, while object material controls do not leak into the hotspot API.

const spotIds = presenter.getSpotIds();
console.log(spotIds);

await presenter.addSpot('hotspotA', {
  primitive: 'sphere',
  size: 50,
  position: [-300, 0, 200],
  color: 0xff4d6d
});

const appearance = presenter.getSpotAppearance('hotspotA');
presenter.setSpotAppearance('hotspotA', {
  color: 0xffc857,
  alpha: 0.85,
  highlightColor: 0xffffff,
  highlightAlpha: 1
});

// A pointer or picking handler can drive this state.
presenter.setSpotHighlighted('hotspotA', true);
presenter.setSpotHighlighted('hotspotA', false);

presenter.removeSpot('hotspotA');

Spot transforms use the same position, rotation, scale, and matrix declarations as objects. The shared presenter.getEntityTransform(id) and presenter.setEntityTransform(id, update) methods work for both namespaces; use an identifier that is unambiguous or keep object and spot identifiers distinct when calling them.

Spot clicks

Assign onSpotClicked for the simple 3DHOP-compatible form. The callback receives the clicked spot identifier first. Spot clicks are generated on primary-button release and are suppressed when the pointer movement is a navigation drag.

presenter.onSpotClicked = (id) => {
  console.log('Clicked spot:', id);
};

Use the subscription form when several parts of an application need to observe clicks or when the intersection details are useful.

const handleSpotClick = (event) => {
  console.log(event.id, event.point.toArray());
};

presenter.on('spotclick', handleSpotClick);
presenter.off('spotclick', handleSpotClick);

A SpotClickEvent contains id, the world-space intersection point, the owning Three.js object, and the original PointerEvent. Spot clicks are independent of the general picking mode, and only entities from the spots block can produce them.
