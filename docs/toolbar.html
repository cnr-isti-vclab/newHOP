Basic Toolbar

The optional Toolbar is a small set of controls built on the Presenter's public API. It is distributed with newHOP, but the Presenter does not create or require it; an application can use custom controls instead.

Creating a Toolbar

import { Presenter, Toolbar } from '../src/index.ts';

const presenter = new Presenter({ mount: 'viewer' });
const toolbar = new Toolbar(presenter, {
  position: 'bottom-center'
});

The toolbar is mounted in the Presenter's container by default. Set mount to an HTML element or element ID to place it elsewhere. The container is anchored automatically when needed.

Default Buttons

If buttons is omitted, the toolbar contains these items in order:

IDAction
homeRestore the stored Home viewpoint.
fitFit the object scene using the current viewing direction.
zoomInDolly the camera closer.
zoomOutDolly the camera farther away.
fullscreenEnter or leave fullscreen mode for the Presenter container.

Predefined Items

Authors can assemble a toolbar from the complete predefined palette. measure, section, and camera are available when explicitly selected.

IDRoleRepeatable
home, fit, zoomIn, zoomOut, measure, section, camera, fullscreenBuilt-in interactive controls. camera switches between perspective and orthographic projection and is highlighted in orthographic mode.No
spacerFixed-size empty separation.Yes
hardruleFixed-size visual separator.Yes
 
new Toolbar(presenter, {
  position: 'bottom-center',
  buttons: ['home', 'fit', 'spacer', 'measure', 'hardrule', 'fullscreen']
});

Non-repeatable items use their first occurrence. Later duplicates are ignored and reported with console.warn. Spacers and hardrules may be repeated freely.

Custom Buttons

A custom declaration block can combine the public viewer API into an application-specific control. Its icon can be text or a DOM Node.

new Toolbar(presenter, {
  buttons: [
    'home',
    'fit',
    {
      kind: 'custom',
      id: 'front-fit',
      label: 'Fit from front',
      icon: 'F',
      onClick: () => presenter.fitToScene(
        { azimuth: 0, elevation: 0 },
        true,
        600
      )
    }
  ]
});
PropertyMeaning
kindMust be 'custom'.
idApplication-defined identifier. It must be unique among custom buttons.
labelButton tooltip and accessible label.
iconText or a DOM node used as the button graphic.
onClickOptional button-specific handler receiving the mouse event.
toggleOptional active-state styling flag.
isActiveOptional function returning the current active state.

Instead of a handler on each declaration, provide onCustomButton(id, event) on the toolbar configuration. A custom button with its own onClick uses that handler in preference to the shared callback.

Position and Lifecycle

Use setPosition() to change the toolbar position after creation. Call refresh() after application state changes that affect custom active states, and call dispose() when the toolbar is no longer needed.

toolbar.setPosition('top-right');
toolbar.refresh();
toolbar.dispose();
Design boundary: the built-in toolbar is intentionally simple. For custom sizing, layouts, graphics, or more complex interactions, build an application-owned component and call the same public Presenter and manager APIs.
