Navigation and Trackball

The navigation block configures the camera interaction model. The current implementation is a custom turntable trackball with object-in-hand behavior, scene-aware fitting, authored limits, and programmatic viewpoint control.

Navigation configuration example

Example configuration for the navigation block, specifying the type, limits, and initial view.


navigation: {
  type: 'turntable',
  homeView: {
    target: [0, 50, 0],
    azimuth: -35,
    elevation: 18,
    distance: 1000
  },
  limits: {
    azimuth: [-90, 90],
    elevation: [-10, 60],
    distance: [500, 2500],
    pan: {
      x: [-250, 250],
      y: [-200, 250],
      z: [-250, 250]
    }
  }
}

General Properties

General properties select the navigation mode and basic interaction behavior.


type: 'turntable',
upAxis: 'y',
verticalAxisLocked: true
PropertyMeaningUnitsDefault
typeNavigation mode. turntable is the current default; sphere is reserved for the alternate mode.Identifierturntable
upAxisWorld axis treated as vertical by the camera orbit and base grid. Use 'y' for computer graphics -style scenes or 'z' for survey and engineering scenes.'y' | 'z''y'
verticalAxisLockedPrevents vertical axis while dragging.Booleanfalse

At runtime, use the corresponding Trackball methods:


presenter.trackball.setMode('turntable');
presenter.trackball.setUpAxis('z');
presenter.trackball.setVerticalAxisLocked(true);

The up-axis changes camera navigation and base-grid orientation only. Mesh coordinates, object transforms, picked points, and measurement results remain in their authored XYZ coordinate system. Pan limits remain literal world-axis x, y, and z ranges.

Content alignment

Use world.sceneTransform to align all authored content without rotating the camera, base grid, axes, or explicit world-space section planes. A content transform is applied above each object's local transform and is included in scene bounds, picking, and measurements.

world: {
  sceneTransform: {
    rotation: [0, 0, 20]
  }
}

Update or inspect the content transform at runtime with presenter.setSceneTransform(update) and presenter.getSceneTransform(). Component transforms use degrees and may specify position, rotation, or scale; a column-major matrix can be used instead, but matrix and component fields cannot be mixed.

Home View

Specifies the view restored by the initial scene setup and by Trackball reset operations, including target, azimuth, elevation, and distance.


homeView: {
  target: [0, 50, 0],
  azimuth: -35,
  elevation: 18,
  distance: 1000
}
PropertyMeaningUnitsDefault
homeView.targetHome point around which the camera orbits. If omitted, it is the computed scene center.Scene unitsScene center
homeView.azimuthHorizontal orbit angle. If omitted, it is frontal view. Degrees0
homeView.elevationVertical orbit angle. If omitted, it is no elevation.Degrees0
homeView.distanceHome camera distance. If omitted, it is fitted from scene bounds.Scene unitsAutomatic fit

At runtime, update the home view with the same object structure:

presenter.trackball.setHomeView({
  target: [0, 50, 0],
  azimuth: -35,
  elevation: 18,
  distance: 1000
});

To return to this configured home view, use the semantic reset operation:

presenter.trackball.reset();

Limits

Specifies the limits for camera navigation, including azimuth, elevation, distance, and pan ranges.

Azimuth and elevation limits are angular ranges in degrees. Distance and pan limits use scene units. Pan limits are absolute world-space target coordinates.

limits: {
  azimuth: [-90, 90],
  elevation: [-10, 60],
  distance: [500, 2500],
  pan: {
    x: [-250, 250],
    y: [-200, 250],
    z: [-250, 250]
  }
}

For unrestricted horizontal rotation, omit azimuth, use azimuth: 'free', or use the legacy [-180, 180] convention.

PropertyMeaningUnitsDefault
azimuthHorizontal rotation range. Use 'free' or omit it for unlimited rotation.DegreesFree
elevationVertical rotation range. Values are clamped below the poles.Degrees[-70, 70]
distanceMinimum and maximum camera distance from the target.Scene units[0.01, 10000]
pan.xAbsolute minimum and maximum target X coordinate.Scene unitsFree
pan.yAbsolute minimum and maximum target Y coordinate.Scene unitsFree
pan.zAbsolute minimum and maximum target Z coordinate.Scene unitsFree

At runtime, pass a partial or complete limits object to the Trackball:

presenter.trackball.setLimits({
  azimuth: [-90, 90],
  elevation: [-10, 60],
  distance: [500, 2500],
  pan: {
    x: [-250, 250],
    y: [-200, 250],
    z: [-250, 250]
  }
});

Speed

Speed settings control how quickly the camera responds to user input.

Rotation and panning speeds are applied per pointer pixel. Zoom speed controls the exponential wheel sensitivity. These values are dimensionless controls, while the resulting distance and pan movement remain in scene units.

navigation: {
  speed: {
    rotate: 0.008,
    pan: 0.0015,
    zoom: 0.001
  }
}
PropertyMeaningUnitsDefault
rotateRotation sensitivity per pointer pixel.Radians per pixel0.008
panPan sensitivity relative to camera distance.Scale factor0.0015
zoomExponential mouse-wheel zoom sensitivity.Scale factor0.001

At runtime, use the same speed structure. Partial updates leave omitted values unchanged:

presenter.trackball.setSpeed({
  rotate: 0.004,
  pan: 0.001,
  zoom: 0.0005
});

Accessing Navigation State at Runtime

It is possible, at runtime, to access the current navigation state through the Presenter or Trackball.

The status snapshot includes the current mode, input-lock state, target, camera position, up vector, angles, distance, and all active limits. Unlimited limits are represented by null.


const status = presenter.getNavigationStatus();
// or: presenter.trackball.getStatus()

console.log(status.azimuth);              // degrees
console.log(status.elevation);            // degrees
console.log(status.distance);             // scene units
console.log(status.target);               // current pan target
console.log(status.navigationEnabled);
console.log(status.limits);

Observing Navigation Changes at Runtime

It is possible to register a navigation change listener with the Presenter. This allows you to react to navigation changes in real-time, keeping your UI in sync with the user's interactions.

This feature can be used to implement html-based live UI components such as compasses, minimaps, orientation indicators, and custom 3D widgets. The callback receives the current Trackball status immediately when subscribed and again after every navigation change, including animation frames.


const unsubscribe = presenter.onNavigationChange((status) => {
  compass.setAzimuth(status.azimuth);
  compass.setElevation(status.elevation);
  minimap.setTarget(status.target);
});

// When the widget is removed:
unsubscribe();

This is event-driven and synchronized with the Presenter render state, to avoid a continuous polling of getNavigationStatus().

Multiple subscriptions can be active simultaneously, allowing different UI components to react independently to navigation changes. Each callback may be unsubscribed individually using the returned function.

Controlling Navigation at Runtime

Navigation can be programmatically controlled at runtime using viewpoints, changing the camera position and orientation as needed.

For the turntable trackball, a viewpoint is defined by the orbit target and its three orbit parameters: azimuth, elevation, and distance. These are the native Trackball state values.


const viewpoint = {
  target: [0, 50, 0],
  azimuth: 35,
  elevation: 18,
  distance: 1000
};

presenter.jumpToViewpoint(viewpoint);
presenter.animateToViewpoint(viewpoint);       // default: 1500 ms
presenter.animateToViewpoint(viewpoint, 800);  // explicit duration

Resetting to Home

reset() returns the Trackball to the configured homeView. It is intended for Home buttons and shortcuts; use jump or animate for arbitrary viewpoints.

presenter.trackball.reset();

Fitting the Scene

presenter.fitToScene(direction, recenter, duration) fits the object scene in the camera view. Fitting uses the object bounding-box corners directly, with no additional padding; helpers, grids, and spots do not contribute to the fit.

ParameterMeaningDefault
directionScene-relative { azimuth, elevation } in degrees. If omitted, the current viewing direction is preserved.Current direction
recenterIf true, move the orbit target to the scene center. If false, preserve the current target.false
durationAnimation duration in milliseconds. A positive value animates the fit; zero applies it immediately.0

Requested directions are clamped to the navigation limits without raising an error. Fitting never changes the authored homeView, so reset() still returns to Home.

presenter.fitToScene();
  presenter.fitToScene({ azimuth: 90, elevation: 0 }, true, 600);

When no homeView is authored, the load-time fit supplies the default Home viewpoint.

For integrations that need raw camera vectors, presenter.trackball.getCameraViewpoint() returns a compatibility snapshot containing target, position, and up. It can be applied with setCameraViewpoint(), but turntable code should prefer orbit viewpoints.

Jump

jumpToViewpoint immediately applies the target and cancels any active animation.

Animate

animateToViewpoint smoothly interpolates to the target. User drag, wheel input, reset, or another immediate viewpoint command interrupts the animation.

Toolbar

The optional Toolbar component is a public-API client. It is not created by the Presenter, and applications may replace it with their own controls.

With no buttons list, the toolbar contains home, fit, zoomIn, zoomOut, and fullscreen. Additional predefined buttons are available by explicit selection: measure and section.

new Toolbar(presenter, {
  position: 'bottom-center',
  buttons: ['home', 'fit', 'spacer', 'measure', 'hardrule', 'fullscreen']
});

spacer and hardrule are fixed-size layout items and may be repeated. Other predefined IDs are used only at their first occurrence; later duplicates are ignored with a console warning.

Custom buttons use declaration blocks. Their icon may be text or a DOM node. Provide either a button-specific onClick or the toolbar-level onCustomButton callback.

new Toolbar(presenter, {
  buttons: [
    'home',
    {
      kind: 'custom',
      id: 'front-fit',
      label: 'Fit from front',
      icon: 'F',
      onClick: () => presenter.fitToScene({ azimuth: 0, elevation: 0 }, true, 600)
    }
  ]
});

Locking User Input

Locking user input prevents the user from interacting with the navigation controls, but programmatic control remains available.

When locked, pointer rotation, panning, and wheel zoom are ignored. Jump, animation, reset, and viewpoint restoration still work.


presenter.setNavigationEnabled(false);

// do some programmatic motion while navigation is locked
presenter.animateToViewpoint(viewpoint);

presenter.setNavigationEnabled(true);

Double-click Re-centering

Double-clicking a visible model or geometry entity recenters the turntable target on the picked surface point and zooms in slightly. Hotspots and helpers are ignored. The behavior is also disabled while navigation input is locked.

Programmatically, the same behavior is available through:


presenter.recenterOnEntityPoint(point);
presenter.recenterOnEntityPoint(point, 0.85); // optional zoom factor
