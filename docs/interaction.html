Interaction

newHOP keeps camera navigation, object picking, hotspot activation, measurement, and clipping as separate tools. This page describes which tool owns each pointer interaction and which entities it can affect.

Generic picking and spot clicks are completed-click interactions. A navigation drag must not activate either tool.

Generic object picking

Enable picking mode and register one active pick handler. The handler is intended to receive a world-space intersection result when the pointer interaction qualifies as a click or tap.

presenter.picking.setOnPick((result) => {
  console.log('Object:', result.entityId);
  console.log('Point:', result.point.toArray());
});
presenter.setPickingMode(true, {
  marker: { size: 5, color: 0xff5533 }
});

The generic-picking contract is intentionally object-only. It resolves a hit on imported child geometry back to its owning managed object, so application code can identify the newHOP object rather than depending on an incidental child Three.js node. Spots use their separate click API, and helpers never produce generic pick results.

Pointer down records the candidate interaction. The pick is resolved on pointer release only when movement remains within the click threshold. Pointer movement beyond 5 CSS pixels cancels the pending pick, and pointer cancellation discards it. This keeps orbit, pan, and other navigation gestures from invoking the pick handler.

Once implemented, the pick result will expose the world-space point, an intersection normal, the low-level hit object, the owning managed object identity, and pointer input metadata such as button, pressed buttons, pointer type, and keyboard modifiers. The exact TypeScript shape follows the PickingManager implementation.

Picking does not currently define application-level pickable or pick-through policy. Those behaviors remain application-dependent and are intentionally deferred.

Picking mode displays one unlit feedback point at the latest picked position by default. It remains hidden until the first successful pick and uses depth testing, so geometry can occlude it. The default marker.depthOffset is 0.5 screen pixels toward the camera, avoiding surface z-fighting without assuming whether world units are millimeters or meters. Configure marker.visible, marker.size in CSS pixels, marker.color, marker.opacity, marker.depthTest, and marker.depthOffset through the optional second argument to setPickingMode. For an always-visible translucent point, use { depthTest: false, opacity: 0.3 }. The marker is hidden and cleared when picking mode is disabled. The optional basic toolbar exposes the same interaction as a pickpoint button. Its attached panel shows the picked managed object ID and point as [x, y, z]; it remains hidden until pickpoint mode is active.

Spot clicks

Spots are interactive annotations with their own namespace and event contract. Spot clicks are independent of generic picking mode and are dispatched only for completed primary-button interactions.

presenter.onSpotClicked = (id, event) => {
  console.log('Clicked spot:', id, event.point.toArray());
};

presenter.on('spotclick', (event) => {
  console.log(event.id, event.originalEvent.pointerType);
});

Use the compatibility callback when one application handler is enough. Use the subscription form when multiple parts of an application need the same event. See the Spots reference for the complete event shape and runtime spot API.

Navigation input

The supported navigation mode is turntable. Left-button dragging orbits. Shift plus left-button, middle-button, and right-button dragging pan. The wheel controls zoom. Touch input supports one-finger orbit, two-finger pan, and pinch zoom.

A stationary right-button click leaves the browser context menu available. The context menu is suppressed only after a right-button drag. Double-clicking ordinary scene content recenters navigation on the picked world point; hotspot double-clicks are ignored.

See the Navigation and Trackball reference for viewpoint configuration, limits, input locking, and runtime navigation controls.

Measurement and clipping

Measurement is enabled with presenter.setMeasurementMode(true). Applications can subscribe to completed measurements through the measurement manager. Measurement input is separate from generic picking, so enabling one tool does not implicitly enable the other.

Clipping is configured with presenter.setClipPlane(axis, offset, enabled). The clipping manager owns section-plane state; it does not change which objects are eligible for generic picking.
